📦 LangGraph State Schema

class CodeFillState(TypedDict):
    # 사용자 정보
    user_id: str
    session_id: str
    
    # 대화 히스토리
    messages: List[BaseMessage]
    
    # 문제 정보 (수집 단계에서 채워짐)
    problem_name: Optional[str]
    problem_type: Literal["blank", "puzzle", "dialog"]
    language: str
    difficulty: str
    info_complete: bool  # 정보 수집 완료 여부
    
    # RAG 결과
    retrieved_context: Optional[str]
    original_problem_id: Optional[str]
    rag_success: bool  # RAG 검색 성공 여부
    
    # 생성된 문제
    generated_problem: Optional[dict]
    
    # Sandpack 풀이 상태
    user_code: Optional[str]  # 사용자 작성 코드
    trigger_type: Literal["hint", "execute", None]  # 트리거 유형
    
    # 실행 결과 (답체크 + 디버깅 통합)
    execution_result: Optional[dict]  # {success, output, error}
    error_type: Optional[str]  # syntax/runtime/logic/none
    error_analysis: Optional[str]  # LLM 에러 분석 결과
    test_passed: int  # 통과한 테스트 수
    test_total: int  # 전체 테스트 수
    
    # 힌트 상태 (힌트봇 ↔ 답체크봇 동기화)
    hint_level: int  # 0, 1, 2, 3
    hint_history: List[str]  # 제공된 힌트 목록
    
    # 결과
    is_correct: Optional[bool]
    feedback: Optional[str]
    xp_earned: int
    gold_earned: int

🔑 핵심 설계 포인트

  • Info Router: 정보 충분 시 RAG, 부족 시 재질문 루프
  • RAG Router: 검색 성공 시 Type Router, 실패 시 Code Gen Agent로 LLM 코드 생성
  • Sandpack 트리거: 실행 버튼(▶️) 클릭 시 답체크 + 디버깅 챗봇 자동 트리거
  • 힌트 ↔ 답체크 동기화: hint_level 공유, 에러 분석 결과 기반 힌트 자동 제공
  • 답체크 통합: 실행/검증/에러분석/피드백/재시도유도를 하나의 노드에서 처리
  • DB 분리: 기존 problems DB는 읽기 전용, 생성된 문제는 user별 테이블에 저장
  • v3.2+ 확장: 커리큘럼 Agent, 튜터 Agent는 Info Collector 앞단에 연결
